# Инструкции Codex для `backend/`

## Ответственный

Основной владелец backend: Dex.

## Стек

- Python 3.11;
- FastAPI;
- Pydantic;
- SQLAlchemy 2;
- Alembic;
- MySQL 8.4;
- официальный Python SDK OpenAI;
- Pytest.

## Структура

Предпочтительная минимальная структура:

```text
backend/
├── app/
│   ├── api/
│   ├── core/
│   ├── db/
│   ├── models/
│   ├── schemas/
│   ├── services/
│   │   └── ai/
│   └── main.py
├── migrations/
├── tests/
├── Dockerfile
└── requirements.txt
```

Создавай только те модули, которые реально используются.

## Правила реализации

- HTTP-маршруты должны быть тонкими: валидация, вызов сервиса, формирование ответа.
- Бизнес-логику размещай в `services/`.
- AI-вызовы изолируй в `services/ai/`.
- Для входных и выходных данных используй Pydantic-схемы.
- Доступ к БД выполняй через SQLAlchemy; изменения схемы фиксируй Alembic-миграциями.
- Не возвращай клиенту stack trace, SQL-ошибки, секреты или внутренние промпты.
- Добавь `/api/v1/health`; при необходимости отдельно проверяй доступность БД.
- CORS настраивай через переменную окружения, а не значением `*` для произвольного production-развёртывания.
- Для ожидаемых ошибок возвращай подходящий HTTP-код и понятное сообщение.
- Минимально протестируй health endpoint, основной успешный сценарий и один некорректный запрос.

## Интеграция

- Контракт с frontend хранится в корневом `API_CONTRACT.md`.
- При изменении схемы сначала обнови контракт и предупреди frontend-разработчика.
- Не меняй файлы `frontend/`, если задача не требует совместного исправления.
