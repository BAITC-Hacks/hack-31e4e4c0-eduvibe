# API-контракт frontend ↔ backend

Контракт согласован для конкурсного MVP EduVibe. Все пути имеют префикс `/api/v1`, тела передаются как JSON, время — ISO 8601 UTC.

## Общие правила

### Кабинеты и приватность (обновление по запросу команды)

- `GET /demo/profiles` — публичные демонстрационные профили бизнеса и команд.
- `POST /session` с `{role: "business"|"student", profile_id: string}` возвращает `{token, role, profile_id, name}`. Это явно обозначенный демовход без пароля, а не проверка личности.
- Остальные endpoints, кроме health, требуют `Authorization: Bearer <token>`. Сессия действует 12 часов; `DELETE /session` отзывает её, `GET /session` возвращает профиль.
- Роль и владелец определяются сервером по случайному токену. Без сессии — 401, чужое действие — 403; недоступный черновик — 404.
- `GET /tasks/mine` — все неудалённые кейсы текущего бизнеса, включая черновики.
- `POST /tasks`, редактирование, AI, ответы, подтверждение, публикация и `DELETE /tasks/{id}` разрешены только бизнесу-владельцу.
- `PATCH /tasks/{id}` принимает `card` и необязательные `topic`, `description`. До подтверждения каталог использует прежний снимок карточки и рейтинг.
- `DELETE /tasks/{id}` возвращает 204: кейс скрывается, отклики сохраняются в базе; повторное удаление — 404.
- `GET /tasks` и просмотр опубликованного кейса возвращают подтверждённый снимок, без вопросов и ответов AI. Владельцу `GET /tasks/{id}` возвращает рабочую версию.
- `GET /tasks/{id}/proposals` и решения бизнеса доступны только владельцу кейса. Чужая компания и любая студенческая команда получают 403.
- `POST /tasks/{id}/proposals` доступен студенту. Поле `team_id` удалено из запроса: команда определяется сессией, подмена через тело запроса отклоняется.
- `GET /me/proposals` возвращает только отклики текущей команды. Автор видит свой текст и решение; остальные студенты не видят ни текст, ни список чужих откликов.
- Отклик дополнительно содержит `task_title`, `task_deleted`, `milestone_confirmed`.
- Профиль бизнеса добавлен как `owner_id` к задаче. Старые задачи при миграции принадлежат демонстрационному бизнесу `business-demo`.
- Демовход позволяет сознательно переключаться между всеми тестовыми профилями; для настоящих пользователей необходима проверка личности. Приватность проверяется в пределах выбранной серверной сессии.

- Backend URL локально: `http://localhost:8000/api/v1`.
- Swagger: `http://localhost:8000/docs`.
- После редактирования карточка требует нового подтверждения.
- Владелец редактирует и удаляет свои кейсы. Каталог показывает последнюю подтверждённую версию до подтверждения правок.
- Низкий рейтинг не запрещает публикацию или отклик.
- Каталог возвращает только опубликованные задачи, по убыванию рейтинга.
- `ai_mode` равен `live` для OpenAI и `fallback` для явно обозначенного резервного режима.

## Единый формат ошибки

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Проверьте введённые данные.",
    "details": [{"field": "description", "message": "String should have at least 10 characters"}]
  }
}
```

Основные коды: `VALIDATION_ERROR` — 422, `UNAUTHORIZED` — 401, `FORBIDDEN` — 403, `*_NOT_FOUND` — 404, нарушение состояния — 409, проблемы AI — 502/503/504.

## Структуры

### Карточка `card`

```json
{
  "title": "Каталог практических задач",
  "context": "Как процесс работает сейчас",
  "need": "Что нужно изменить",
  "users": "Кто пользуется решением",
  "data_materials": "Доступные данные и примеры",
  "constraints": "Сроки, технологии и доступы",
  "expected_result": "Конкретный результат",
  "success_criteria": "Измеримые признаки успеха",
  "contact": "Контакт бизнеса",
  "interaction_format": "Формат консультаций и обратной связи"
}
```

Все поля — строки. Лимит исходного описания — 5000 символов.

### Рейтинг `readiness`

```json
{
  "total": 55,
  "level": "working",
  "level_label": "Рабочая",
  "breakdown": [
    {
      "field": "context",
      "label": "Контекст",
      "points": 10,
      "max_points": 10,
      "hint": null
    }
  ],
  "missing_information": ["Критерии успеха"],
  "suggestions": ["Добавьте измеримые признаки успешного результата."]
}
```

Уровни: `draft` 0–39, `working` 40–69, `ready` 70–89, `priority` 90–100.

### Задача

Ответ задачи содержит:

```json
{
  "id": "uuid",
  "owner_id": "business-demo",
  "description": "Исходное описание",
  "topic": "Образование",
  "card": {},
  "questions": [],
  "answers": [],
  "readiness": {},
  "is_confirmed": false,
  "is_published": false,
  "ai_mode": null,
  "created_at": "2026-09-23T10:00:00",
  "updated_at": "2026-09-23T10:00:00"
}
```

## Endpoints

| Метод | Путь | Вход | Результат |
|---|---|---|---|
| GET | `/health` | — | `{"status":"ok","database":"ok"}` |
| GET | `/demo/profiles` | — | `businesses[]: {id, name}`, `teams[]` с навыками и баллами |
| POST | `/session` | `role`, `profile_id` | `token`, `role`, `profile_id`, `name` |
| GET | `/session` | Bearer | `role`, `profile_id`, `name` |
| DELETE | `/session` | Bearer | 204, отзыв сессии |
| POST | `/tasks` | `description`, `topic` | 201, черновик с исходным рейтингом |
| GET | `/tasks/mine` | — | Черновики и публикации текущего бизнеса |
| GET | `/tasks/{id}` | — | Владельцу рабочая версия, другим — публичный снимок |
| DELETE | `/tasks/{id}` | — | 204, владелец скрывает кейс из кабинета и каталога |
| POST | `/tasks/{id}/clarifications` | — | `questions` (не менее 3), `ai_mode` |
| PUT | `/tasks/{id}/answers` | `answers[]: {question_id, field, text}` | Обновлённая карточка и предварительный рейтинг |
| PATCH | `/tasks/{id}` | `card`, необязательные `topic`, `description` | Полная замена карточки; подтверждение сбрасывается |
| POST | `/tasks/{id}/confirm` | — | Подтверждённая карточка и зафиксированный рейтинг |
| POST | `/tasks/{id}/publish` | — | Опубликованная задача; без порога баллов |
| GET | `/tasks?topic=...&readiness_level=...` | Оба фильтра необязательны | Каталог |
| GET | `/teams` | — | Пять демонстрационных профилей |
| POST | `/tasks/{id}/proposals` | `idea`, `plan`, `duration_days`, `prototype_url` | 201, отклик команды из сессии |
| GET | `/me/proposals` | — | Только собственные отклики студенческой команды, включая историю удалённых кейсов |
| GET | `/tasks/{id}/proposals` | — | Только владельцу: отклики с профилями команд |
| PUT | `/tasks/{id}/decision` | `selected_proposal_ids[]`, `rejected_proposal_ids[]` | Все отклики с новыми статусами |
| PUT | `/proposals/{id}/milestone` | `result`, `points` (1–100) | Подтверждённый этап и общий балл команды |

Отклик содержит `id`, `task_id`, `task_title`, `task_deleted`, `team_id`, `team` (профиль), `idea`, `plan`, `duration_days`, `prototype_url`, `status`, `milestone_confirmed`, `created_at`. Статусы: `pending`, `selected`, `rejected`.

`idea` и `plan`: 10–4000 символов после удаления внешних пробелов. Срок: 1–365 дней. Ссылка: HTTP(S), не длиннее 500 символов. Лишние поля запроса отклика, включая `team_id`, возвращают 422.

Ответы заменяют соответствующие поля карточки; повторное сохранение не дописывает тот же текст. ID вопроса и поле должны соответствовать последнему набору вопросов. Пустые сведения не заполняются автоматически.

Обновление уточняющих вопросов очищает ответы на прежний набор вопросов, сохраняя уже внесённые в карточку сведения.

### Пример уточняющих вопросов

```json
{
  "questions": [
    {"id": "q-1", "field": "users", "text": "Кто будет пользоваться результатом решения?"},
    {"id": "q-2", "field": "data_materials", "text": "Какие данные доступны команде?"},
    {"id": "q-3", "field": "success_criteria", "text": "По каким признакам вы примете результат?"}
  ],
  "ai_mode": "live"
}
```

### Решение бизнеса

```json
{
  "selected_proposal_ids": ["proposal-1"],
  "rejected_proposal_ids": ["proposal-2"]
}
```

Запрос задаёт полное решение: не перечисленные отклики переходят в `pending`. Пустые массивы допустимы и возвращают все отклики на рассмотрение. Чтобы отклонить всех, передайте все ID в `rejected_proposal_ids`. Один ID нельзя передать в обоих массивах. Автоматического выбора нет.

## Правило рейтинга

Баллы начисляются за непустые поля последней подтверждённой версии:

| Поле | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт бизнеса | 5 |
| Формат взаимодействия | 5 |

Название и тема обязательны для представления задачи, но не входят в 100 баллов.
