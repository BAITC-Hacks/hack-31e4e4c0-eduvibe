# Проверка кабинетов — 2026-09-23

Проверено после запроса Dex о разделении бизнеса и студентов. Официальные требования кейса не расширялись: роли, приватность и управление своими кейсами оформлены как уточнение команды в `TASK_BRIEF.md`.

## Автоматические проверки

- `python -m pytest -q` в backend-контейнере, Python 3.11: **11 passed**, одно предупреждение устаревшего API библиотеки Starlette/AnyIO.
- `npm run build` при сборке frontend-контейнера: TypeScript и Vite завершились успешно.
- `git diff --check`: ошибок форматирования нет.
- Миграция существующей MySQL: `0001 → 0002`, данные не удалялись.
- Чистая установка: отдельный Compose-проект `eduvibe-rolecheck`, новый volume MySQL и `.env.example`; три сервиса запустились, Alembic достиг `0002`. Рабочий volume не использовался.

Тесты backend воспроизводятся командами из README. Они проверяют сессии, владение, приватность между двумя бизнесами/командами, валидацию, выбор нескольких команд/отклонение всех, однократное подтверждение этапа, публичный снимок и историю удаления.

## Сквозная браузерная проверка

Временный Playwright/Chromium запускался вне зависимостей приложения. Две отдельные браузерные сессии использовали реальный frontend и HTTP API с MySQL.

| Действие | Результат |
|---|---|
| Выбрать бизнес и открыть команды | Отдельный кабинет, пять профилей команд |
| Создать кейс про доставку выпечки | Собственный черновик, исходная готовность |
| Вызвать помощника | `ai_mode=live`, шесть контекстных вопросов |
| Ответить, подтвердить, опубликовать | Ответы в редактируемой карточке, рейтинг 90/100, публикация |
| Войти студентом и найти кейс | Опубликованное ТЗ, нет кнопок управления и AI |
| Отправить идею, план, срок и ссылку | Предложение появилось у владельца и в собственных откликах |
| Запросить общий список откликов от студента | HTTP 403 |
| Выбрать команду бизнесом | Студент видит «Команда выбрана» |
| Сохранить правки опубликованного ТЗ | Студент видит прежнюю версию до подтверждения |
| Подтвердить правки | Студент получает новую версию |
| Удалить кейс | В каталоге отсутствует, история собственного отклика сохранена |
| Сменить роль | Возврат к экрану входа, сессия отозвана |

Пример реального вопроса: «Какие данные доступны для анализа и использования (например, история заказов, адреса, время доставки)?» Другие вопросы затрагивали пользователей-диспетчеров и курьеров, распределение заказов, маршруты и уменьшение опозданий.

На чистой установке без ключа повторён тот же сценарий с видимым `fallback`. Дополнительно обновлены вопросы после сохранения ответов: новые поля ответов пустые, ранее внесённые факты в карточке сохранены. В обоих завершённых браузерных сценариях ошибок JavaScript нет. Проверка резервного сценария сначала остановилась из-за неточного локатора теста; после исправления локатора прошла полностью.

## Границы проверки

- Это демонстрационные профили без пароля. Сервер ограничивает запросы по сессии, но посетитель может сознательно выбрать чужой тестовый профиль. Для приватности реальных пользователей нужна аутентификация.
- Браузерный прогон выполнен на настольном Chromium; другие браузеры и мобильные устройства отдельно не проверялись.
- Репетиция выступления с ограничением в пять минут и окончательная проверка всех условий допуска остаются задачами команды.
- Подробный сценарий ручного повтора — в README. Тексты и количество вопросов live AI могут различаться между вызовами.
