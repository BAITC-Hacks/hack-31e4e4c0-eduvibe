# EduVibe

EduVibe помогает бизнесу превратить короткое описание практической задачи в проверяемую карточку с рейтингом готовности, а студентам — найти задачу и отправить предложение.

MVP содержит отдельные кабинеты бизнеса и студентов, интегрированные React/Vite frontend, FastAPI backend, MySQL, AI-интеграцию, миграции и синтетические данные. Компоненты взаимодействуют по [API_CONTRACT.md](API_CONTRACT.md).

## Что реализовано

- выбор роли и демонстрационного профиля при входе;
- бизнесу — свои кейсы и каталог студенческих команд;
- создание, редактирование и удаление собственных кейсов;
- студентам — опубликованные кейсы и собственные отклики;
- приватные предложения: владелец кейса видит все отклики, команда — только свои;
- черновик из темы и свободного описания;
- исходный рейтинг и прозрачная шкала 0–100;
- минимум три уточняющих вопроса через OpenAI или явно отмеченный резервный режим;
- ответы, ручное редактирование и подтверждение карточки;
- публикация без минимального порога рейтинга;
- каталог с сортировкой, фильтрами по теме и уровню готовности;
- пять профилей команд и пять демонстрационных задач/откликов;
- неограниченные отклики;
- ручной выбор, отклонение или отсутствие выбранных команд;
- однократное подтверждение одного этапа выбранной команды;
- единый формат ошибок и серверная валидация.


## Архитектура

```text
React/Vite frontend → FastAPI backend → OpenAI API
                              ↓
                           MySQL 8.4
```

Backend хранит карточки, команды и отклики в MySQL. Модуль AI только выявляет пробелы и формирует вопросы; рейтинг рассчитывается детерминированно сервером. Сформированные сведения редактируются и подтверждаются человеком.

AI-помощник находится в кабинете бизнеса и помогает заказчику уточнить ТЗ обычными словами. Студенты видят подтверждённую карточку. Редактирование опубликованного кейса сохраняет прежнюю публичную версию до подтверждения изменений владельцем. Удаление скрывает кейс из каталога и кабинета; история отправленных предложений остаётся у команд.

## Формула рейтинга

Баллы начисляются за непустые поля подтверждённой карточки:

| Показатель | Баллы |
|---|---:|
| Контекст и потребность | 10 + 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и формат взаимодействия | 5 + 5 |

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. Низкий рейтинг не скрывает опубликованную задачу и не запрещает отклик.

## Быстрый запуск

Требуются Docker и Docker Compose.

```bash
cp .env.example .env
# При наличии ключа заполните OPENAI_API_KEY в .env
docker compose up --build
```

После запуска:

- Frontend: http://localhost:5173
- API: http://localhost:8000/api/v1
- Swagger: http://localhost:8000/docs
- health check: http://localhost:8000/api/v1/health

Миграция Alembic и идемпотентное создание синтетических данных выполняются при старте backend. Данные MySQL сохраняются в Docker volume.

При обновлении существующей установки достаточно `docker compose up --build -d`. Миграция `0002` назначает старые кейсы профилю «Бизнес · Практика» и сохраняет их публичную версию. Не удаляйте volume при обновлении: `docker compose down -v` уничтожает данные.

Без `OPENAI_API_KEY` система использует локальные контекстные шаблоны вопросов и возвращает `ai_mode: "fallback"`. Этот режим предназначен для разработки и резервной демонстрации и не выдаётся за реальный вызов AI.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI; секрет не хранится в Git | пусто |
| `OPENAI_MODEL` | Модель для вопросов | `gpt-4.1-mini` |
| `OPENAI_TIMEOUT_SECONDS` | Таймаут AI | `20` |
| `AI_FALLBACK_ENABLED` | Разрешить обозначенный fallback | `true` |
| `CORS_ORIGINS` | Разрешённые origin через запятую | `http://localhost:5173` |
| `VITE_API_URL` | URL API для frontend | `http://localhost:8000/api/v1` |
| `MYSQL_*` | Локальная конфигурация MySQL | см. `.env.example` |

## Локальная проверка backend

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cd backend
PYTHONPATH=. ../.venv/bin/pytest -q

# Frontend
cd ../frontend
npm ci
npm run build
```

Проверка контейнера:

```bash
curl http://localhost:8000/api/v1/health
curl http://localhost:8000/api/v1/demo/profiles
```

Для остальных запросов получите сессию через `POST /api/v1/session` с `{"role":"business","profile_id":"business-demo"}` и передавайте возвращённый токен в `Authorization: Bearer <token>`. В Swagger нажмите Authorize. Сессия действует 12 часов и отзывается кнопкой «Сменить роль».

Backend-тесты проверяют полный сценарий, валидацию, отсутствие/истечение сессии, запреты чужих действий, приватность откликов, обновление опубликованного снимка, удаление с сохранением истории и однократное начисление баллов. AI в unit-тестах работает в резервном режиме без ключа; реальный вызов проверяется отдельно.

Фактические результаты проверки кабинетов: [docs/ROLE_CHECK.md](docs/ROLE_CHECK.md).

## Демонстрационный сценарий

1. На стартовом экране выбрать «Я представляю бизнес» и профиль «Бизнес · Практика».
2. В «Мои кейсы» создать кейс из темы и описания. Нажать «Помочь составить ТЗ», проверить уместность вопросов и отметку реального AI либо резервного режима.
3. Ответить на вопросы, внести ответы в карточку, отредактировать сведения. Подтвердить ТЗ, показать рейтинг и опубликовать кейс.
4. Через «Сменить роль» войти студентом и выбрать команду. Найти кейс в каталоге, открыть полное ТЗ и отправить идею, пример решения, план, срок и ссылку.
5. В «Мои отклики» проверить своё предложение. У другой команды оно не отображается.
6. Вернуться в тот же профиль бизнеса, открыть кейс → «Предложения команд». Сравнить отклики, выбрать одну/несколько команд или отклонить все; сохранить решение.
7. В кабинете студента обновить статусы. При необходимости бизнес подтверждает один этап выбранной команды (+10 баллов в UI).
8. Бизнес может изменить и снова подтвердить опубликованное ТЗ либо удалить кейс. После удаления кейс исчезает из каталога, история собственного отклика остаётся у студента.

Сценарий проходит через frontend; для диагностики API также доступен Swagger.

## Обработка ошибок и безопасность

Ввод ограничен по длине и проверяется Pydantic. Без действующей сессии API возвращает 401, при попытке чужого действия — 403, для недоступного черновика — 404. Неверные состояния возвращают 409, некорректный ввод — 422, проблемы AI — 502/503/504 при отключённом fallback. Ключ OpenAI передаётся только backend через окружение. AI получает тему, описание и заполненную карточку, поэтому используйте синтетические данные без секретов.

## Известные ограничения

- нет регистрации и проверки личности: каждый посетитель может выбрать любой тестовый профиль. Сервер ограничивает доступ в рамках выбранной сессии, но демонстрационный вход не обеспечивает приватность между реальными людьми; перед реальным использованием необходима аутентификация;
- полнота оценивается по подтверждённому заполнению полей, без субъективной оценки качества текста;
- формула баллов команды за прогресс не задана организаторами; в API доступно ручное значение 1–100;
