# EduVibe

EduVibe помогает бизнесу превратить короткое описание практической задачи в проверяемую карточку с рейтингом готовности, а студентам — найти задачу и отправить предложение.

Версия 0.1 содержит интегрированные React/Vite frontend, FastAPI backend, MySQL, AI-интеграцию, миграции и синтетические данные. Компоненты взаимодействуют по [API_CONTRACT.md](API_CONTRACT.md).

## Что реализовано

- черновик из темы и свободного описания;
- исходный рейтинг и прозрачная шкала 0–100;
- минимум три уточняющих вопроса через OpenAI или явно отмеченный резервный режим;
- ответы, ручное редактирование и подтверждение карточки;
- публикация без минимального порога рейтинга;
- каталог с сортировкой, фильтрами по теме и уровню готовности;
- пять профилей команд и пять демонстрационных задач/откликов;
- неограниченные отклики;
- ручной выбор, отклонение или отсутствие выбранных команд;
- однократное подтверждение одного этапа выбранной команды;
- единый формат ошибок и серверная валидация.


## Архитектура

```text
React/Vite frontend → FastAPI backend → OpenAI API
                              ↓
                           MySQL 8.4
```

Backend хранит карточки, команды и отклики в MySQL. Модуль AI только выявляет пробелы и формирует вопросы; рейтинг рассчитывается детерминированно сервером. Сформированные сведения редактируются и подтверждаются человеком.

## Формула рейтинга

Баллы начисляются за непустые поля подтверждённой карточки:

| Показатель | Баллы |
|---|---:|
| Контекст и потребность | 10 + 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт и формат взаимодействия | 5 + 5 |

Уровни: 0–39 — черновик, 40–69 — рабочая, 70–89 — готовая, 90–100 — приоритетная. Низкий рейтинг не скрывает опубликованную задачу и не запрещает отклик.

## Быстрый запуск version 0.1

Требуются Docker и Docker Compose.

```bash
cp .env.example .env
# При наличии ключа заполните OPENAI_API_KEY в .env
docker compose up --build
```

После запуска:

- Frontend: http://localhost:5173
- API: http://localhost:8000/api/v1
- Swagger: http://localhost:8000/docs
- health check: http://localhost:8000/api/v1/health

Миграция Alembic и идемпотентное создание синтетических данных выполняются при старте backend. Данные MySQL сохраняются в Docker volume.

Без `OPENAI_API_KEY` система использует локальные контекстные шаблоны вопросов и возвращает `ai_mode: "fallback"`. Этот режим предназначен для разработки и резервной демонстрации и не выдаётся за реальный вызов AI.

## Переменные окружения

| Переменная | Назначение | Значение по умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | Ключ OpenAI; секрет не хранится в Git | пусто |
| `OPENAI_MODEL` | Модель для вопросов | `gpt-4.1-mini` |
| `OPENAI_TIMEOUT_SECONDS` | Таймаут AI | `20` |
| `AI_FALLBACK_ENABLED` | Разрешить обозначенный fallback | `true` |
| `CORS_ORIGINS` | Разрешённые origin через запятую | `http://localhost:5173` |
| `VITE_API_URL` | URL API для frontend | `http://localhost:8000/api/v1` |
| `MYSQL_*` | Локальная конфигурация MySQL | см. `.env.example` |

## Локальная проверка backend

```bash
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cd backend
PYTHONPATH=. ../.venv/bin/pytest -q

# Frontend
cd ../frontend
npm ci
npm run build
```

Проверка контейнера:

```bash
curl http://localhost:8000/api/v1/health
curl 'http://localhost:8000/api/v1/tasks?readiness_level=priority'
```

Тесты проверяют health, единый ответ на некорректный ввод и полный сценарий: черновик → вопросы → рост рейтинга → подтверждение → публикация → отклик → решение → баллы.

## Демонстрационный сценарий

1. Создать слабый черновик через `POST /tasks`.
2. Получить вопросы через `POST /tasks/{id}/clarifications` и обратить внимание на `ai_mode`.
3. Сохранить ответы, отредактировать карточку и показать рост рейтинга.
4. Подтвердить и опубликовать задачу.
5. Найти её в каталоге с фильтром.
6. Выбрать профиль из `GET /teams` и отправить отклик.
7. Вручную выбрать или отклонить отклик.
8. При необходимости подтвердить один этап выбранной команды.

Сценарий проходит через frontend; для диагностики API также доступен Swagger.

## Обработка ошибок и безопасность

Ввод ограничен по длине и проверяется Pydantic. Неверные состояния возвращают 409, некорректный ввод — 422, проблемы AI — 502/503/504. Ключ OpenAI передаётся только backend через окружение. AI получает только описание задачи и заполненные поля; персональные и чувствительные признаки не используются.

## Известные ограничения

- нет регистрации: используются демонстрационные профили;
- полнота оценивается по подтверждённому заполнению полей, без субъективной оценки качества текста;
- формула баллов команды за прогресс не задана организаторами; в API доступно ручное значение 1–100;
