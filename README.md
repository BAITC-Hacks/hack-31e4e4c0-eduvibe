# EduVibe v2

MVP по кейсу AI Sana «Рейтинг качества бизнес-задач и открытый выбор команд», трек «Образование». Бизнес описывает потребность, уточняет её с AI, подтверждает карточку и публикует задачу. Студенты самостоятельно выбирают кейсы, отправляют приватные предложения; бизнес вручную выбирает одну, несколько или ни одной команды.

В v2 объединены frontend из ветки `FronteendV2` и backend с серверными сессиями. Функциональная карта — навигация по настоящим полям ТЗ: «Проблема», «Результат», «Условия работы».

## Быстрый запуск

Нужны Git, Docker и Docker Compose. Порты 5173 и 8000 должны быть свободны.

```bash
git clone git@github.com:BAITC-Hacks/hack-31e4e4c0-eduvibe.git
cd hack-31e4e4c0-eduvibe
git checkout v2.0.0
cp .env.example .env
# Добавьте OPENAI_API_KEY в .env для реального AI.
docker compose up --build -d
docker compose ps
curl http://localhost:5173/api/v1/health
```

- Сайт: http://localhost:5173
- API: http://localhost:8000/api/v1
- Swagger: http://localhost:8000/docs
- Ожидаемый health: `{"status":"ok","database":"ok"}`.

При запуске автоматически применяются Alembic-миграции и создаются синтетические данные. Без ключа работает явно обозначенный резервный режим вопросов; он не выдаётся за ответ модели.

Для обновления существующей установки сохраните свой ключ в `.env`, задайте `VITE_API_URL=/api/v1` и выполните `docker compose up --build -d`. MySQL хранит данные в volume. `docker compose down` сохраняет volume; **`docker compose down -v` удаляет данные** и не требуется при обновлении.

### Демонстрация по локальной сети

Откройте `http://IP_КОМПЬЮТЕРА:5173` с другого устройства той же сети. Frontend обращается к относительному `/api/v1`; существующий Vite-сервис передаёт запросы backend внутри Compose. Браузеру не нужен адрес `localhost:8000`, отдельный reverse proxy не добавлен. Порт 5173 должен быть доступен через локальный firewall.

Если frontend и API намеренно размещены на разных адресах, задайте абсолютный `VITE_API_URL`, добавьте точный origin frontend в `CORS_ORIGINS` и пересоберите контейнеры. Не используйте `*` вместо списка origin.

По уточнению команды добавлены отдельные кабинеты, серверное владение кейсами, редактирование публикаций и удаление. Пока бизнес редактирует опубликованное ТЗ, студенты видят предыдущую подтверждённую версию. После подтверждения обновляются карточка, рейтинг и позиция. Удаление скрывает кейс из каталога и кабинета, сохраняя историю предложения у его автора.

## Демонстрация до пяти минут

1. **0:00–0:40.** Войти как «Бизнес · Партнёр». Создать тему «Доставка выпечки» и слабое описание: «В пекарне диспетчер вручную распределяет доставки между курьерами. Адреса ведём в таблице, заказы опаздывают». Показать исходный рейтинг.
2. **0:40–1:50.** Открыть «AI-вопросы», получить вопросы. Ответить только известными фактами, перенести ответы в карту.
3. **1:50–2:40.** Показать заполненные узлы, изменить одно поле, сохранить. Показать рост рейтинга, расшифровку и оставшиеся пробелы. Подтвердить и опубликовать.
4. **2:40–3:40.** Во второй вкладке/браузере войти командой, найти кейс фильтром и отправить идею, план, срок и ссылку `https://example.com/prototype`.
5. **3:40–4:30.** В кабинете бизнеса открыть «Отклики» и нажать «Обновить отклики». Выбрать или отклонить предложение и зафиксировать решение. У студента открыть «Мои отклики» → «Обновить статусы».
6. **4:30–5:00.** При выборе команды подтвердить один фактически показанный этап и показать начисленные баллы.

Это план выступления; укладывание команды в пять минут нужно отрепетировать. Готовый пример можно подготовить заранее, но переходы на защите выполняются в приложении.

Синтетические ответы для подготовки: пользователи — диспетчер и пять курьеров; данные — 20 тестовых заказов; срок — две недели; результат — веб-прототип распределения; критерий — распределить 20 заказов за 5 минут. Это демонстрационные вводимые сведения, они не подставляются моделью автоматически.

## Архитектура и данные

```text
Браузер → React + TypeScript + Vite (:5173)
                    ↓ /api/v1
             FastAPI, Python 3.11 (:8000) → OpenAI API
                    ↓ SQLAlchemy 2
                MySQL 8.4 + Alembic
```

Всего три сервиса: frontend, backend, db. Очередей, Redis и отдельных микросервисов нет.

- `backend/app/api` — HTTP-маршруты; `schemas` — валидация.
- `services/tasks.py` — жизненный цикл кейса, каталог, предложения, решение, этап.
- `services/access.py` — демонстрационные сессии и проверка роли/владельца.
- `services/ai/clarifications.py` — промпт, вызов OpenAI, проверка ответа и fallback.
- `services/rating.py` — детерминированная формула рейтинга.
- `models`, `migrations` — задачи, команды, предложения, этапы и хеши сессионных токенов.
- `frontend/src/CaseWorkspace.tsx` — карта ТЗ, вопросы, рейтинг и решения бизнеса.
- `frontend/src/Views.tsx` — создание, каталог, карточки, профили и история откликов.

Миграция `0002` сохраняет старые задачи, назначает их профилю `business-demo` и создаёт снимки уже опубликованных карточек. `app.seed` содержит исходные синтетические описания, отрасли и карточки. При чистом запуске создаются все минимальные наборы из ТЗ; повторный запуск не дублирует их и не восстанавливает удалённые пользователем демонстрационные черновики.

## Формула рейтинга

| Подтверждённое непустое поле | Баллы |
|---|---:|
| Контекст | 10 |
| Потребность | 10 |
| Данные и материалы | 20 |
| Ожидаемый результат | 15 |
| Критерии успеха | 15 |
| Ограничения | 10 |
| Пользователи | 10 |
| Контакт бизнеса | 5 |
| Формат взаимодействия | 5 |

Название и тема нужны для представления задачи и не входят в 100 баллов. До подтверждения показывается **предварительный расчёт** по сохранённым полям. Подтверждение фиксирует баллы; каталог использует последний подтверждённый снимок.

Уровни: **0–39** — черновик, **40–69** — рабочая, **70–89** — готовая, **90–100** — приоритетная. Уровень «черновик» по баллам не равен неопубликованному черновику: опубликованный кейс с низким рейтингом виден всем командам.

Рейтинг оценивает заполненность полей, а не истинность и содержательное качество текста. Одинаковые баллы упорядочиваются по ID; компания и персональные признаки участников на оценку не влияют.

## AI: вход, выход, ограничения

Настройка по умолчанию — `gpt-4.1-mini`, JSON mode и серверная Pydantic-валидация. Полный системный промпт находится в [clarifications.py](backend/app/services/ai/clarifications.py). Вход: `topic`, `initial_description`, `current_card`. Пример результата:

```json
{"questions":[
  {"id":"q1","field":"users","text":"Кто будет пользоваться результатом?"},
  {"id":"q2","field":"data_materials","text":"Какие данные доступны команде?"},
  {"id":"q3","field":"success_criteria","text":"Как вы проверите успешность решения?"}
]}
```

Проверяются количество вопросов, допустимые и неповторяющиеся поля, непустой текст. Сервер назначает уникальные ID. Если пустых полей меньше трёх, вопросы уточняют детали заполненных полей; модель не заполняет их сама. Ответы пользователя заменяют соответствующие поля карточки, остаются редактируемыми и требуют подтверждения.

Таймаут, отсутствие ключа, ошибка API и некорректный ответ приводят к явному `ai_mode: "fallback"`, если он разрешён. При отключённом fallback API возвращает контролируемые 502/503/504. В логах указывается категория ошибки; ключи и тексты ошибок провайдера с потенциальными секретами не печатаются. Таймаут одного запроса задаётся окружением, автоматические повторы SDK отключены.

Сохранённый `ai_mode` описывает **последнюю генерацию вопросов этого кейса**, а не текущую доступность OpenAI. Для новой попытки нажмите «Обновить уточняющие вопросы». Прежние ответы на вопросы очистятся, но уже внесённые в ТЗ факты сохранятся.

AI получает описание и заполненную карточку. Используйте синтетические данные без секретов; автоматического удаления персональных данных из свободного текста нет. Модель не оценивает студентов и не назначает команды. Ограничения JSON mode и необходимость серверной проверки описаны в [официальной документации OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs).

## API-контракт

Префикс `/api/v1`, JSON. Полные схемы — в Swagger. Кроме `health`, `demo/profiles` и создания сессии, нужен `Authorization: Bearer <token>`.

| Метод и путь | Назначение / доступ |
|---|---|
| GET `/health` | Проверка API и подключения к БД |
| GET `/demo/profiles` | Демонстрационные бизнес-профили и команды |
| POST `/session` | `{role: "business" или "student", profile_id}` → `{token, role, profile_id, name}` |
| GET, DELETE `/session` | Текущий профиль / отзыв сессии (204) |
| POST `/tasks` | `{topic, description}` → черновик (201), только бизнес |
| GET `/tasks/mine` | Кейсы текущего бизнеса |
| GET `/tasks?topic=...&readiness_level=...` | Опубликованный каталог, фильтры необязательны |
| GET `/tasks/{id}` | Владельцу рабочая версия; остальным подтверждённая публикация без AI-вопросов и ответов |
| PATCH `/tasks/{id}` | `{card, topic?, description?}`, полная замена карточки; только владелец |
| DELETE `/tasks/{id}` | Мягкое удаление владельцем (204) |
| POST `/tasks/{id}/clarifications` | `{questions, ai_mode}`, только владелец |
| PUT `/tasks/{id}/answers` | `{answers: [{question_id, field, text}]}`, только владелец |
| POST `/tasks/{id}/confirm` | Подтверждение, пересчёт и обновление существующей публикации |
| POST `/tasks/{id}/publish` | Публикация подтверждённой карточки без порога баллов |
| GET `/teams` | Профили и баллы команд |
| POST `/tasks/{id}/proposals` | `{idea, plan, duration_days, prototype_url}` → отклик (201), только студент |
| GET `/me/proposals` | Только отклики команды из сессии |
| GET `/tasks/{id}/proposals` | Только владельцу кейса: все предложения |
| PUT `/tasks/{id}/decision` | `{selected_proposal_ids: [], rejected_proposal_ids: []}`, только владелец |
| PUT `/proposals/{id}/milestone` | `{result, points}`, только владелец кейса выбранной команды |

У задачи есть `owner_id`, `card`, `readiness`, `questions`, `answers`, `is_confirmed`, `is_published`, `ai_mode`. У отклика — данные предложения, `team`, `task_title`, `task_deleted`, `milestone_confirmed` и статус `pending|selected|rejected`. Команда определяется сессией: передача `team_id` в отклике отклоняется.

Решение заменяется целиком: ID вне двух списков переходят в `pending`; пустые списки означают «все на рассмотрении». Чтобы отклонить всех, передайте все ID в `rejected_proposal_ids`. Один ID в обоих списках запрещён.

Ошибки: `{"error":{"code":"...","message":"...","details":[]}}`. Нет сессии — 401, чужое действие — 403, недоступный/удалённый кейс — 404, нарушение состояния — 409, неверный ввод — 422. Тексты идеи и плана: 10–4000 символов; срок: 1–365 целых дней; HTTP(S)-ссылка до 500 символов; результат этапа: 10–4000 символов, баллы: 1–100.

Тесты принудительно используют SQLite **в памяти**, пустой ключ и отдельный engine. К рабочей MySQL они не подключаются. Проверяются сессии/истечение/отзыв, границы ролей и владельцев, приватность двух команд, весь жизненный цикл, повторные ответы, снимок публикации, удаление с историей, выбор нескольких команд, отклонение всех, однократный этап, валидация, ошибки AI и минимальные объёмы seed. Тесты AI имитируют ответы провайдера; реальный вызов проверяется отдельно через интерфейс.

Локальная разработка frontend: `cd frontend && npm ci && npm run dev`, API должен работать на 8000. Для локального backend задайте `DATABASE_URL` доступной БД и из каталога backend выполните `alembic upgrade head`, `python -m app.seed`, `uvicorn app.main:app --reload`. В рабочей демонстрации используйте Compose с MySQL.

## Ограничения и организационные вопросы

- Демонстрационный вход не проверяет личность: посетитель может выбрать любой тестовый профиль. Сервер запрещает чужие действия в пределах выбранной сессии, но для реальных пользователей нужна аутентификация. Сессия живёт 12 часов, токен в sessionStorage, в базе только его SHA-256.
- Нет регистрации, чата, уведомлений, календаря, загрузки файлов, собственного ML и полного проектного трекера: это прямо исключено из обязательного объёма кейса. Ссылки на прототипы не загружают файлы.
- Формула командных баллов в ТЗ не задана. В MVP бизнес вручную назначает 1–100 за один подтверждённый этап; она не влияет на рейтинг готовности кейса.
- Полноценная мобильная адаптация, высокая нагрузка и промышленный деплой не заявляются. Vite preview используется для хакатонной демонстрации.
- В кейсе указано 3–5 участников, фактическая команда состоит из двух: допуск нужно подтвердить у организаторов. Время официального старта/закрытия и выполнение почасового регламента не устанавливаются кодом.
- Репетиция выступления до пяти минут остаётся обязанностью команды.
